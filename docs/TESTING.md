# Testing

## What was actually executed when this version was produced
The environment used to write this code had **no Gradle, Maven, Android SDK or network access to Maven repositories**, so the
two Gradle projects could **not be built or run there**. What was possible, and done:

| Check | How | Result |
|---|---|---|
| Shared rules (password, nickname, roles/permissions, board templates & keys, ordering, rate limiter) | real Kotlin compiler 2.0.21, 14 tests, server copy | **14/14 pass** |
| Same rules, Android copy (generated by `tools/sync_shared_rules.sh`) | same tests, compiled separately | **14/14 pass** |
| Activity sentences, board filters, WIP states, drag geometry (column hit-test, insertion index, edge scroll, hold vs drag), due-date calendar maths, filtered→real drop index | compiled + run | **16/16 pass** |
| Error classification & user messages (`ErrorKind`, `ErrorMessages`) | compiled + run | **4/4 pass** |
| Syntax of **every** `.kt` file (96 files) | tree-sitter parse | **0 errors** (it caught 3 real problems, all fixed) |
| Every project-internal `import` resolves to a declaration | script | **0 unresolved** (only generated `BuildConfig`) |
| Palette contrast | `python3 tools/contrast_check.py` | 38 checks, all ≥ 4.5:1 |

**Not executed here (you must run them):** `./gradlew test` for both projects, the Ktor end-to-end tests
(`server_app/src/test/kotlin/ApiIntegrationTest.kt`, 9 scenarios against in-memory H2), Android compilation, and anything that
needs a device. Code that uses Ktor/Exposed/Compose/Room/Hilt was written against the pinned library versions but has **not been
type-checked by a compiler** - expect to fix a handful of small compile errors on first build (typically a missing import or a
renamed overload). Icons are centralised in `ui/icons/AppIcons.kt`, so an icon-name mismatch is a one-file fix.

## Run
```bash
cd server_app  && ./gradlew test
cd android_app && ./gradlew test
python3 tools/contrast_check.py
./tools/sync_shared_rules.sh   # after editing server_app/.../domain/*.kt
```

## Manual test checklist (device / emulator)
1. **Auth** - sign up with a weak password: every rule shows ✗ and the button is disabled; fix them one by one and watch ticks turn green. Log in, kill the app, reopen: still signed in.
2. **Settings** - switch Light / Dark / Automatic: whole app changes immediately and survives a restart. Edit nickname (try 1 char, 31 chars, `<b>`): inline error. Username row is locked.
3. **Change password** - wrong current password → error under that field; weak new password → button disabled; success → snackbar; log in from a second device with the old password fails.
4. **Boards** - create (template chips), search, grid/list toggle, pull to refresh; ⋮ menu: Rename / Empty / Delete as admin, only *Open* as viewer.
5. **Board** - new board has *To Do, In Progress, In Review, Done*. Hold a card ~0.4 s → it lifts; drag across columns (edges auto-scroll), blue line shows the slot; release. Drop into *Done* → confetti. Hold **without moving** → sheet: Rename, Replan, Assign, Priority, Move to, Delete; each works and appears in **Activity**.
6. **WIP** - set limit 1, add 2 cards: counter turns red with a warning icon; moving still allowed (info snackbar).
7. **Multi-user** - user A creates board, adds B as *Viewer*: B can open but cannot drag/edit (long-press shows only details), server answers 403 if forced. Promote B to *Member*: drag works and A sees the move live. Create a team, give it access, add C to the team → C sees the board.
8. **Offline** - airplane mode, rename/move/create tasks (top pill says "Offline · N changes waiting"), turn network on: changes sync in order; check Activity.
9. **Errors** - stop the server and use the app (friendly "No connection" messages, no crash). Start it with `DEV_API_KEY` set, force an exception (e.g. temporarily throw in a ViewModel) and verify the report arrives at `GET /diagnostics/errors`.
10. **Rotation / process death** on Board, Task and Settings screens.
