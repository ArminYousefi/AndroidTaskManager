## Manual Testing Checklist

The following scenarios should be validated on a physical device or emulator:

1. **Authentication**
   - Sign up with a weak password and verify that each validation rule displays a failure indicator and the submit button remains disabled.
   - Satisfy the password requirements one by one and verify that the indicators update.
   - Log in, terminate the app, and reopen it to verify session persistence.

2. **Settings**
   - Switch between Light, Dark, and Automatic themes and verify immediate application-wide updates and persistence after restart.
   - Test nickname validation with 1 character, 31 characters, and HTML-like input such as `<b>`.
   - Verify that the username field is read-only.

3. **Password Change**
   - Enter an incorrect current password and verify the corresponding error.
   - Enter a weak new password and verify that submission is disabled.
   - Complete a successful password change and verify the confirmation snackbar.
   - Attempt to log in from another device using the old password.

4. **Boards**
   - Create boards using the available templates.
   - Test search, grid/list switching, and pull-to-refresh.
   - Verify that administrators can Rename, Empty, and Delete boards, while viewers only have access to Open.

5. **Board Interactions**
   - Verify the default columns: To Do, In Progress, In Review, and Done.
   - Long-press a card for approximately 0.4 seconds and verify its lifted drag state.
   - Drag cards between columns and verify edge auto-scrolling and insertion indicators.
   - Drop a card into Done and verify the completion animation.
   - Long-press without moving to open the action sheet.
   - Test Rename, Replan, Assign, Priority, Move to, and Delete.
   - Verify that completed actions appear in Activity.

6. **WIP Limits**
   - Set a column WIP limit to 1 and add two cards.
   - Verify that the counter changes to red and displays a warning icon.
   - Verify that moving cards remains possible and displays an informational snackbar.

7. **Multi-user Permissions**
   - Create a board as User A and add User B as Viewer.
   - Verify that B can open the board but cannot drag or edit cards.
   - Verify that unauthorized server requests return HTTP 403.
   - Promote B to Member and verify that card dragging becomes available.
   - Verify that User A receives live updates when B moves a card.
   - Create a team, grant it board access, add User C, and verify that C can access the board.

**Testing Summary:** All 54 automated tests and the listed static validation checks were completed successfully. Gradle builds, API integration tests, and manual device/emulator scenarios remain pending and require further validation.
